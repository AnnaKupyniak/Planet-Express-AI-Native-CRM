# Planet Express AI-Native CRM

Цей проєкт — AI-Native CRM система для кур'єрської служби **Planet Express**.

## Доменна область
Система реалізує облік міжпланетних доставок:

- **User**: Користувачі CRM (авторизація JWT).
- **Client**: Клієнти, які замовляють доставку (MomCorp, Robot Devil тощо). Мають прапорець `is_evil`.
- **Planet**: Планети призначення, мають рівні небезпеки (`danger_level`: low, medium, fatal).
- **CrewMember**: Члени екіпажу. Можуть бути звільнені (`is_fired`).
- **Delivery (Місії)**: Головна сутність (замовлення на доставку). Має назву вантажу, винагороду, статус. *Відносини: 1 клієнт -> багато доставок, 1 планета -> багато доставок.*
- **Assignment**: M:N зв'язок між `Delivery` та `CrewMember` (екіпаж призначається на місію з певною роллю `role_on_ship`).

## AI-Agent Core
- Написаний на Python з використанням OpenAI SDK.
- Працює за сценарієм **multi-step**, логуючи кожен виклик інструменту у `logs/trace.jsonl` (під час демо-скрипта також може використовуватись `logs/capstone-trace.jsonl`).
- Містить вбудовані **Guardrails**: обмеження максимальної кількості кроків (`max_steps`), валідацію вхідних параметрів, та перевірку дозволених інструментів.
- Агент інтегрований з нашим REST API по HTTP. Він самостійно отримує JWT токен для виконання дій.

## Backend (API)
- **Стек**: Node.js, Express, Prisma ORM, PostgreSQL.
- Нормалізована схема БД, міграції, наявність сідів (seed).
- Вбудована валідація даних.
- Усі роути захищені Bearer JWT токеном (крім `/api/auth/login`).
- Додатково реалізовано **GraphQL** ендпоінт (`/api/graphql` або `/graphql`) з data loaders для оптимізації проблеми N+1.

## Як запустити проєкт

1. **Налаштування змінних оточення**:
   Скопіюйте приклади файлів конфігурації в обох сервісах:
   ```bash
   cp api/.env.example api/.env
   cp agent/.env.example agent/.env
   ```
   > **Важливо**: Відкрийте `agent/.env` і вставте ваш реальний `OPENAI_API_KEY`. Без нього агент не зможе працювати!
   
   *Примітка про БД:* У файлі `api/.env`, для запуску в Docker, `DATABASE_URL` повинен використовувати `postgres:5432`. Якщо ви запускаєте базу локально без Docker (або підключаєтесь із локальної машини), порт має бути `localhost:5433`.

2. Запустіть усі контейнери:
   ```bash
   docker-compose up -d
   ```
3. Ініціалізуйте базу даних (це створить таблиці):
   ```bash
   docker-compose exec api npx prisma migrate dev
   ```
4. Наповніть базу даних початковими даними (seed):
   ```bash
   docker-compose exec api npx prisma db seed
   ```
4. API буде доступне за адресою `http://localhost:4000`.
5. Фронтенд (CRM панель) доступний за адресою `http://localhost:5173`.

## Як тестувати

### 1. Тестування API
Для запуску юніт/інтеграційних тестів бекенду (перевірка CRUD, авторизації тощо):
```bash
docker-compose run --rm api npm test
```

### 2. Тестування GraphQL
Ви можете перевірити GraphQL API за допомогою Postman або `curl`.
1. Спершу отримайте токен доступу:
   `POST http://localhost:4000/api/auth/login` з тілом `{"email": "agent@planetexpress.com", "password": "admin123"}`
2. Виконайте запит до `POST http://localhost:4000/graphql` передавши токен у заголовку `Authorization: Bearer <TOKEN>`, і запит у тілі:
   ```json
   { "query": "query { crew { id name role } }" }
   ```

### 3. Capstone Demo (Інтеграційний тест агента)
Щоб запустити агента і виконати демонстраційний багатоступеневий бриф:
```bash
docker-compose run --rm agent python capstone_demo.py
```
Ця команда змусить агента:
- Авторизуватись в API.
- Створити нового клієнта (MomCorp).
- Знайти в БД потрібну планету (Earth).
- Створити нову доставку на цю планету.
- Призначити екіпаж на місію.
- Врешті-решт перевірити коректність збережених даних у БД (зв'язки та відсутність дублікатів).
Трейс операції буде автоматично збережено у `logs/capstone-trace.jsonl` (цей файл створюється під час запуску).
